Library ordering

saved_items is streamed by createdAt DESC.

Collection ordering

collections is streamed by isPinned DESC, then updatedAt DESC.

URL requirement

The SQL constraint type = 'note' OR url IS NOT NULL requires a URL for every non-note row, including links and videos. Notes may store url as NULL.

Note content

Notes require a non-null markdown value. Despite the column name, the editor writes Quill Delta as a JSON string and can also read legacy Markdown. Other item types may leave it null.

Stored values and presentation

Drift stores DateTime values as integer Unix timestamps in seconds. Relative time labels are calculated from created_at in the UI; display_time and duration are not columns in the current schema.

Supported item types

The app recognizes note, link, and video. The database stores type as plain text without an enum constraint, so callers must supply a supported value.

Collection counts

item_count is stored summary data. Note and pocket-link queries update counts transactionally when items are created, deleted, or moved between collections.

Default collection

When a new note or pocket link has no selected collection, the save query finds or creates Read Later. A fresh database starts empty; the current database class defines no custom migration or demo-data seeding strategy.

Database IDs in navigation

go_router routes carry a positive integer ID. The destination resolves that ID from the existing Library or Collections BLoC stream, so opening a detail URL does not depend on a card passing an object through extra.

Route Record lookup
/library/notes/:idsaved_items.id with type = 'note'
/library/links/:idsaved_items.id with type = 'link'
/library/links/:id/editThe same pocket-link record, opened for editing
/collections/:idcollections.id; its items match saved_items.collection_id

Loading and recovery

Destinations wait for their data stream, offer retry on a load failure, and show a recovery page for invalid IDs or missing records. A note URL cannot resolve a pocket-link record.

Stable editor state

Once an item opens, its initial snapshot stays with that screen. Database emissions preserve editor input and allow a delete flow to return its navigation result before the screen unmounts.
